# 자유민턴 실시간 운영 완결판 기준서

최종 갱신: 2026-08-31  
운영 기준: Cloudflare state-worker + D1 + Durable Object + 사용자 웹앱 + 관리자 APK  
검증된 체크포인트: git tag `stable-20260831`

이 문서는 자동배정·경기종료·사용자 우선 저장·알림 동작의 기준 문서다. 오류 수정과 배포 전에 반드시 이 문서를 확인하며, 화면만 존재하고 실제 호출이 연결되지 않은 상태를 완료로 보지 않는다.

1~7장은 관리자 mutation 기준(자동배정/경기종료/저장우선순위/알림), 8장부터는 사용자 웹·앱 UX 기준이다. 구글 스크립트 코드를 참고하거나 복사해도 되지만, 복붙만으로 끝내면 아래 "구현 현황" 표시가 빠진 채로 남는다 — 새 기능을 붙일 때마다 반드시 이 문서의 15장(완료 조건)·16장(구현 연결)에 항목을 추가하고, 기존 항목은 지우지 말고 남긴다.

## 1. 자동배정

- 관리자 화면에는 항상 **자동배정** 버튼이 있어야 한다.
- 코트 1~4 또는 대기 1~5의 빈자리 중 원하는 곳을 1~4칸 선택할 수 있다.
- 서로 다른 코트·대기의 빈자리도 연속 선택할 수 있다.
- 빈자리 선택은 다시 누르면 취소된다.
- 빈자리 선택 후 자동배정 버튼을 한 번 누르면 선택한 자리를 즉시 채운다.
- 관리자 수동 회원 선택이 있으면 그 회원을 우선 사용하고, 없으면 아직 코트·대기에 배정되지 않은 active 회원을 후보로 사용한다.
- 사용자가 먼저 자신을 코트나 대기에 배정한 경우 해당 위치와 회원은 자동배정 후보에서 제외하여 반드시 보존한다.
- 4명을 완성할 수 있을 때 우선 조합은 남자 4명, 여자 4명, 남자 2명+여자 2명이다.
- 마지막 인원으로 복식 조합을 완성할 수 없으면 성별 기준을 무시하고 남은 인원을 최대한 배정한다.
- 4명을 채울 수 없어도 1~3명을 가능한 만큼 배정한다.
- 한 위치에 최대 4명까지만 들어간다.
- 서버 저장 성공 응답을 받은 뒤 관리자 화면을 즉시 갱신한다.
- 충돌 시 사용자의 최신 배정을 우선하고 관리자는 남은 자리만 다시 채운다.

## 2. 경기종료

- 코트에 0~4명 어느 상태라도 경기종료 버튼을 누를 수 있다.
- 종료 즉시 기존 코트 인원을 종료 처리하고 대기1 인원을 해당 코트로 이동한다.
- 대기2→대기1, 대기3→대기2, 대기4→대기3, 대기5→대기4로 즉시 승급한다.
- 관리자 화면과 사용자 웹앱은 저장된 동일 상태로 자동 갱신한다.
- 관리자 기기는 “몇 번 코트 종료”와 대기1 입장자 이름·닉네임을 포함한 안내를 3회 재생한다.
- 안내 중 음성은 최대 볼륨으로 하고 음악은 들리는 수준으로 낮췄다가 안내 종료 후 원래 볼륨으로 복원한다.
- 관리자는 1회 재생, 반복 재생, 멈춤을 사용할 수 있다.

## 3. 사용자 알림

- 종료 직전 대기1에서 코트로 들어가는 사용자에게 해당 코트 입장 팝업과 3회×8묶음 진동을 보낸다.
- 대기2에서 새 대기1로 올라간 사용자에게 라켓 준비 팝업과 동일 진동을 보낸다.
- 사용자가 확인을 누르면 진동은 즉시 멈춘다.
- 확인하지 않으면 안내가 끝날 때까지 반복한다.
- FCM 토큰은 현재 선택된 회원 ID와 매핑되어야 한다.

## 4. 실시간 저장 우선순위

1. 사용자 본인의 최신 배정 요청을 먼저 저장한다.
2. 관리자는 최신 상태를 다시 읽고 남은 위치만 수동 또는 자동으로 채운다.
3. 관리자 화면은 빠른 탐색·저장·갱신을 제공하되 사용자의 이미 저장된 위치를 덮어쓰지 않는다.
4. 모든 mutation은 D1/Durable Object의 단일 최신 revision을 기준으로 처리한다.
5. 관리자·사용자 화면은 Cloudflare의 동일 상태를 사용한다.

# 사용자 웹·앱 UX 기준 (8장부터)

운영 형태: **사용자 웹**(`https://jayuminton-push.web.app/`, 앱 미설치 — 팝업·진동을 페이지 내부에서 처리) / **사용자 앱**(APK 설치 — 네이티브 팝업을 띄우며 네이티브 진동). 같은 화면·같은 로직을 쓰되 팝업·진동 전달 경로만 `window.NativeUserApp` 브리지 유무로 갈린다.

## 8. 로그인 유지 (자동 재진입)

**요구사항**: 관리자가 알려준 비밀번호로 한 번 들어가면, 비밀번호가 바뀌지 않는 한 다음 접속부터는 비밀번호를 다시 묻지 않고 자동으로 들어가야 한다.

- 구현 현황: **이미 구현되어 있음.** 페이지 로드 시 `currentMemberSessionToken()`(localStorage `MEMBER_AUTH_KEY`/세션 토큰)이 있으면 `server('resumeMemberSession',[token])`을 자동 호출해 로그인 화면(`memberLoginBox`)을 건너뛰고 바로 앱으로 진입한다.
- 확인 필요: 실제 기기에서 며칠 뒤 재방문해도 비밀번호 화면이 안 뜨는지, 관리자가 비밀번호를 바꿨을 때 이 세션이 정상적으로 무효화되고 다시 물어보는지 — 코드 확인은 됐지만 실기기 확인은 아직.

## 9. 정보 버튼 패널

**요구사항**: 별표·사용자이름(별명)·알림on·진동on·앱설치on 등을 보여주는 아주 작은 정보 버튼을 클릭하면 패널이 열린다. 알림 버튼을 누르면 on↔off 토글, 진동도 동일. 앱설치 버튼을 누르면 사용자 앱 다운로드 링크가 열려 바로 받을 수 있다(받은 뒤 오뜨님에게 와서 설치 요청 / 또는 gmail을 주면 비공개 테스터로 등록되어 지속 업데이트 받고 의견을 남길 수 있음 안내). 닫기를 누르면 다시 작은 정보 버튼 상태로 돌아간다.

- 구현 현황: 패널 자체(`memberSelfPanel`/`memberSelfSummary`)와 알림·진동 on/off 토글, 앱설치 버튼(다운로드 링크 연결)은 이미 구현되어 있음.
- **미구현**: "gmail 주소를 받아 비공개 테스터로 등록" 안내/입력 UI는 코드에서 확인되지 않음 — 별도 작업 필요 (Play Console 비공개 테스터 명단에 실제로 등록하는 것까지 포함할지, 안내 문구만 보여줄지 결정 필요).

## 10. 본인 설정 (내 이름 지정)

**요구사항**: 내 이름이 설정되어 있지 않으면 "내 이름을 선택하세요" 안내. 이름 검색으로 찾거나 멤버카드를 한 번 클릭하면 "~님이 본인인가요? (취소 / 네, 저예요)" 확인 후 설정된다. 설정되면 내 카드에 **노란 테두리 두 줄**이 생기고, 흰 동그라미 테두리 안의 검은 바탕 작은 원 안에 흰 별표 + '나' 텍스트가 작게 표시된다.

- 구현 현황: 이름 검색/카드 클릭 → 예쁜 확인창(`jmPrettyConfirm`, "네, 저예요") → `bindMemberIdentity` 저장까지는 이미 구현. 별표+'나' 배지(`.member-self-star`)도 있음.
- **⚠️ 충돌 — 결정 필요**: 이번 세션에 자기 카드 테두리 색을 노랑(`#facc15`)에서 **파랑(`#2563eb`)으로 이미 변경**했다. 이유: 그 시점엔 1회성팀(임시팀) 테두리도 같은 노랑이라 "이게 내 카드인지 임시팀 표시인지" 구분이 안 됐기 때문. 지금 이 스펙대로 자기 카드를 다시 노랑으로 되돌리면 그 충돌이 재발한다. 이후(오늘) 임시팀 쪽은 테두리를 **점선**으로 바꿔서 실선(영구팀)과 모양으로도 구분되게 고쳤으므로, "자기 카드=노랑 실선, 임시팀=노랑 점선"으로 색은 같고 모양만 다르게 갈지, 아니면 지금처럼 자기 카드는 파랑을 유지할지 확정해야 한다.
- **확인 필요**: "두 줄" 표현 — 현재는 두꺼운 outline 1개(4px)로 그려진다. 실제로 이중선(두 개의 분리된 선)을 원하는 것인지, 굵은 선 하나를 "두 줄처럼 두껍게"로 표현한 것인지 확인.

## 11. 카드 표시 규칙

**요구사항**: 코트배정대기·코트·대기·종료·귀가·휴식·도착전 어디에 있든 모든 사용자 이름(닉네임)은 항상 전부 출력된다. 이름 아래 작은 글씨로 급수·구력·특별 메모도 함께 보인다. 찬조는 선물 아이콘 옆에 "찬조", 신규는 NEW 아이콘 옆에 "신규" 표시. 고정팀(대회 준비 등으로 처음부터 팀으로 설정)은 카드 테두리 2줄, 1회성으로 그 게임만 같은 팀인 임시팀은 노란 굵은 테두리 1줄 — 관리자가 설정하면 사용자 화면에도 동기화된다. 표시가 없으면 "알아서 팀 배정하라"는 뜻.

- 구현 현황: 이름 항상 전체 노출, 찬조(`🎁 찬조`)/신규(`NEW 신규`) 배지, 급수/구력/메모 표시는 이미 구현. 팀 테두리는 이번 세션에 정리 완료 — 고정팀은 팀 이름별 고유 색 실선(4px outline), 임시팀은 노란(`#facc15`) 점선(4px outline), 관리자·사용자 양쪽 동일 로직(같은 팔레트/해시 함수)이라 항상 동기화된다.
- **확인 필요**: "고정팀 2줄" 표현도 10장과 동일하게 실제 이중선인지 재확인 필요.

## 12. 자기 카드 상태변경 + 메모 입력

**요구사항**: 자기 카드를 길게 누르면 도착전/코트배정대기로/휴식/귀가/내 정보 입력 버튼이 뜬다. "내 정보 입력"을 누르면 구력 글씨 크기 정도의 아주 작은 글씨로 메모를 넣을 수 있다(예: "C조, 구력4년", "생일"). 입력돼 있으면 버튼이 "수정"으로 바뀐다. 문구를 지우고 저장하면 메모 없는 원래 상태로 돌아간다. 메모 글씨색은 "사용자가 직접 입력했다"는 걸 표시하기 위해 화려한 색으로 한다. 이 메모는 관리자 카드에도 자동 반영되며 관리자는 관리자가 쓴 것 + 사용자가 쓴 것을 함께 읽어 수정/편집할 수 있다 — 이때도 화려한 글씨색은 유지한다.

- 구현 현황: 길게 눌러 뜨는 상태변경 버튼시트(도착전/코트배정대기/휴식/귀가/내 정보 입력)와 인라인 메모 입력(`updateMyProfile`, 입력됨→수정 버튼 전환)은 이미 구현.
- **확인 필요**: "화려한 색"이 실제로 어떤 색으로 지정돼 있는지, 관리자 화면에서 사용자가 쓴 메모와 관리자가 쓴 메모가 같은 화려한 색으로 표시되는지 — 코드 레벨 확인 안 됨.

## 13. 빈자리 이동 & 상대방과 자리교환

**요구사항**: 자기 자신은 이미 설정돼 있으므로, 빈자리(코트 1~4 전체, 대기 1~5 전체 모두)를 클릭하면 그 자리에 "저장중"을 띄우며 바로 배치된다. 빈자리가 아닌 상대방 카드(코트 1~4, 대기 1~5, 코트배정대기 전부 포함 모든 위치)를 한 번 클릭하면 "~님과 자리교환을 요청할까요?"(취소/교환 요청) → 상대방에게 "교환요청을 수락하시겠습니까?"(예/아니오) → 예면 자리 바뀜, 아니오면 안 바뀜. 5분 내 응답 없으면 요청 실패.

- 구현 현황:
  - **대기조 빈자리**: 이번 세션에 완료 — 한 번 탭하면 바로 `memberMoveToWaitGroup`로 이동, "저장 중" 오버레이도 뜬다(더블탭/내 카드 재탭 요구 없앰).
  - **자리교환**: 코트/활성 인원(`handleAnywhereMemberTap`)과 대기조(이번 세션에 통일)까지 모든 위치에서 동일한 `memberRequestAnywhereSwap` 경로로 작동. 확인창은 예쁜 팝업(`jmPrettyConfirm`)으로 통일됨. 5분 타임아웃은 서버(`requestSwapMutation`의 `expiresAt: nowMs + 300000`)에 이미 있음.
  - **저장 중 표시 범위**: 이번 세션에 `server()`의 mutationNames 허용 목록을 확장해서 본인설정/메모저장/교환요청/수락/거절/상태변경까지 전부 "저장 중" 오버레이 + 중복클릭 방지가 적용되도록 고침.
- **❌ 미구현 — 새로 만들어야 함**: **코트(1~4번) 빈자리는 사용자 화면에서 아예 클릭할 수 없다.** 현재 `renderCourts()`는 사용자용 빈 코트 슬롯을 `memberCard(null,false,false)`로 렌더링하는데, 이건 `onclick`이 없는 단순 "비어 있음" 표시일 뿐이다. 대기조 빈자리처럼 탭하면 바로 이동하는 기능이 코트 쪽엔 없음 — 이게 이번 "큰 공사"에서 실제로 새로 붙여야 할 핵심 기능.

## 14. 현황갱신 · 대기승급 · 코트입장 알림

**요구사항**: 오른쪽 상단 현황갱신 버튼으로 언제든 화면 갱신 가능. 대기2→대기1로 오르면 "대기1순위입니다. 라켓 들고 준비해주세요" 팝업 + 강한 진동 3×8회(확인 누르면 중간에 멈춤). 대기1에서 코트로 들어가면 "~번 코트 나왔습니다" + 대기1에 있던 4명 정보 팝업 + 동일 진동. 이때 대기2→1, 3→2, 4→3, 5→4로 전원 자동 승급하고, 새로 대기1이 된 사람에게도 같은 팝업+진동이 간다.

- **이 항목은 3장(사용자 알림)과 동일한 요구사항이다.** 팝업 문구·진동 패턴·확인 시 즉시 멈춤·대기 전원 자동 승급까지 3장에 이미 기준으로 명시돼 있고 구현도 돼 있음 — 새로 적을 필요 없이 3장을 그대로 따른다.
- **이번에 추가된 조건**: 사용자 웹(앱 미설치)은 페이지 내부 팝업+진동, 사용자 앱(설치됨)은 네이티브 팝업+네이티브 진동으로 갈라져야 한다는 조건은 기존 3장에 명시돼 있지 않았다. `window.NativeUserApp` 브리지(`setVibrationEnabled` 등)가 이미 있어 네이티브 여부를 구분할 수 있는 것으로 보이나, 두 경로 모두 스펙대로 동작하는지 실기기 확인 필요.
